Changelog

Unreleased

Added

  • Add the required salutation CSV column and ${salutation} template variable for recipient-specific greeting prefixes. ${salutation} ${firstName} renders Liebe Erika or Lieber Peter when the CSV contains Liebe or Lieber. CSV files must include the new column.
  • Document greeting templates and update the example CSV and templates.

Changed

  • Convert Mailing to an immutable Java record while retaining its Lombok builder and constructor argument order. Replace JavaBean getters with record accessors (firstname(), surname(), email(), salutation()); setters are no longer available.
  • Require a non-blank email value for every CSV recipient. Rows with a missing, empty, or whitespace-only email field are logged and skipped.
  • Migrate GreenMail from 1.6.15 to 2.1.14, implementing the dependency update proposed in PR #552.
  • Replace Commons Email 1.6.0 with Commons Email 2's Jakarta variant (commons-email2-jakarta 2.0.0-M1, a milestone release) and migrate application and test imports from javax.mail to jakarta.mail for GreenMail 2 compatibility.
  • Use Eclipse Angus Mail 2.0.5 as the shared mail implementation for the application and tests, excluding legacy and duplicate bundled mail implementations.

Tests

  • Adapt recipient and CSV parsing tests to record accessors and verify Mailing value equality, hash codes, and builder support for omitted values.
  • Cover missing email columns/fields and empty or whitespace-only email values, including continued parsing of valid recipients after invalid rows.
  • Cover salutation parsing, rejection of rows without the required column, HTML escaping, and personalized HTML/plain-text delivery through GreenMail.
  • Retain coverage of authenticated SMTPS delivery, MIME content, attachments, invalid credentials, demo mode, and rejection of plaintext fallback.
  • Verify that the executable JAR includes Jakarta Mail/Activation APIs and provider service descriptors without legacy Javax APIs or the test-only GreenMail server.
